# SpendObserver — Android (Kotlin / Compose / Room)

Нативное Android-приложение для учёта доходов и расходов — преемник веб-версии
[SpendObserver](../expenses-tracker). Полностью локальное: без сервера, без
сети, все данные хранятся в SQLite-базе (через Room) внутри песочницы
приложения на устройстве.

Веб-версия (Next.js + IndexedDB) послужила отправной точкой по бизнес-логике
и UX, но больше не развивается и не поддерживается. Android-приложение —
самостоятельный продукт: модель данных и формат файлов здесь свои, совместимость
с веб-версией не требуется.

## Стек

| Слой | Технология | Почему |
|---|---|---|
| Язык | Kotlin | стандарт Google для Android, меньше boilerplate, корутины |
| UI | Jetpack Compose (Material 3) | декларативный UI |
| Хранение | Room (поверх SQLite) | транзакции, индексы, агрегатные запросы, реактивные `Flow` |
| Асинхронность | Kotlin Coroutines + Flow | стандартный способ работать с Room и состоянием экрана |
| Архитектура | MVVM + Repository | ViewModel + StateFlow на экран, Repository оборачивает DAO |
| Навигация | Navigation Compose (type-safe `@Serializable` маршруты) | список трекеров → трекер → запись / редактирование трекера |
| Графики | Vico (Compose-native charting) | активно поддерживается, из коробки работает с Compose |
| DI | ручной `AppContainer` | не усложнять, пока не появится реальная необходимость в Hilt |
| Тесты | JUnit4, Room (androidTest на эмуляторе), Compose UI Test | чистая логика — JVM-тесты, Room и экраны — instrumented |

## Возможности

- **Трекеры** — несколько независимых трекеров (личный/семейный/рабочий),
  у каждого свои теги и записи. Создание (новый трекер сразу открывается),
  переименование, удаление — со стартового экрана и из шапки трекера.
- **Записи** — одно реальное событие (например, один чек): тип доход/расход,
  дата, описание (необязательно) и **части**.
  - У каждой части своя сумма и свои теги; сумма записи — всегда сумма её
    частей, отдельно не хранится.
  - Простая запись — запись из одной части: в форме это одно поле суммы.
  - «Разбить по частям» превращает введённую сумму в **итог по чеку**:
    выделяешь отдельные части (алкоголь, снеки…), а остаток считается сам
    и становится последней частью.
- **Теги двух уровней**:
  - **общие** (где, с кем — «Ашан», «отпуск») ставятся на запись целиком;
  - **обычные** (на что — «продукты», «алко») ставятся на части.
  Тег живёт только на одном уровне; перенести его на другой можно, пока
  он нигде не используется.
- **Калькулятор в полях суммы** — выражения вида `120+50/2`
  (слева направо, как в веб-версии).
- **Аккордеон год → месяц → запись** с количеством записей и итогами на
  каждом уровне. После сохранения/удаления записи аккордеон раскрывается и
  прокручивается к ней (или к месяцу, откуда она удалена); состояние
  раскрытия сохраняется при переходах между экранами.
- **Графики** (план) — разбивка по тегам обоих уровней, топ тегов, навигация
  по годам/месяцам.
- **Импорт/экспорт** (план) — файл трекера, перенос между устройствами.
- **Локализация** (план) — en / ru / fr.

## Модель данных

```
Tracker        (id, title, createdAt, updatedAt, backupAt)
Tag            (id, trackerId, name, isGlobal)
Record         (id, trackerId, date, type, description)        // суммы нет
RecordPart     (id, recordId, amountCents, position)           // ≥ 1 на запись
RecordTag      (recordId, tagId)        // общие теги записи
RecordPartTag  (partId, tagId)          // обычные теги части
```

- Суммы — целые числа в центах (`Long`), никогда не `Float`.
- Итоги записи, месяца, года и трекера **не хранятся**, а считаются из
  частей: в Room-запросах (`JOIN record_parts` + `SUM`, записи считаются как
  `COUNT(DISTINCT r.id)`) или на лету в domain-слое. Денормализованных сумм,
  которые нужно синхронизировать, нет.
- Год и месяц — способ группировки записей по дате, а не сущности.
- Удаление каскадное: трекер → записи → части → связи с тегами.
- Записи с частями и тегами читаются одной read-моделью `RecordWithParts`
  (вложенные `@Relation`).
- Схема экспортируется в `app/schemas/` (Room `exportSchema`). Пока реальных
  данных нет, схема пересобирается в версии 1; с первым релизом — только
  миграции.

## План работ

1. ~~**Инициализация проекта**~~ — готово.
2. ~~**Слой данных**~~ — Room-сущности, DAO, репозитории, тесты на Room.
3. ~~**Domain-слой**~~ — итоги, калькулятор, даты; JVM-тесты.
4. ~~**Список трекеров**~~ — создание, переименование, удаление.
5. ~~**Экран трекера**~~ — аккордеон год/месяц/запись с итогами.
6. ~~**Создание/редактирование записи**~~ — форма, калькулятор, теги.
   ~~**Записи из частей**~~ — части с собственными суммами и тегами, итог
   по чеку с автоостатком, общие/обычные теги.
7. **Графики** — Vico: траты по обычным тегам (суммы частей), по общим
   тегам (суммы записей), топ тегов, навигация по годам/месяцам.
8. **Импорт/экспорт** — собственный формат файла (см. ниже); экспорт через
   Storage Access Framework (`ACTION_CREATE_DOCUMENT`), импорт через
   `ACTION_OPEN_DOCUMENT` с валидацией и выбором слияния/замены, «Поделиться»
   через `Intent.ACTION_SEND`.
9. **Локализация** — `values/strings.xml`, `values-ru/`, `values-fr/`.
10. **Полировка** — тёмная тема, иконка, splash screen, подпись и сборка `.apk`.

## Формат файла экспорта (шаг 8)

Формат свой и проектируется на шаге 8. Что уже решено:

- JSON (kotlinx.serialization) с полем версии формата — чтобы будущие
  изменения модели не ломали импорт старых файлов.
- Отражает текущую модель: записи с частями, теги с признаком `isGlobal`;
  суммы — целые центы; итоги в файл не пишутся (считаются при импорте).
- Внутренние id Room в файле не являются устойчивым ключом: при импорте
  теги сопоставляются по имени, записи и части получают новые id.
- Неизвестные поля — предупреждение, а не отказ в импорте.
- Импорт файлов веб-версии не планируется.

## Превью записи в аккордеоне

Строка записи — три колонки, каждая в своей ширине:

```
| дата | данные                                 | итог     |
| 11   | Теги: [Ashan]                          | -3450.00 |
|      | ▾ 3 части                              |          |
|      | [alko]                        800.00   |          |
|      | [sneki]                       300.00   |          |
|      | [produkty]                   2350.00   |          |
|      | Описание: текст переносится только     |          |
|      | внутри средней колонки                 |          |
```

- Средняя колонка никогда не заезжает текстом на соседние.
- Дата, «Теги:» и итог стоят на одной базовой линии.
- Части многочастной записи по умолчанию свёрнуты («▸ N частей»), чтобы
  обилие данных не загромождало список.
- Общие теги — с заливкой, обычные — с рамкой.

## Явно не в скоупе (пока)

- Синхронизация между устройствами (кроме ручного экспорта/импорта файла).
- Десктопная версия — после Android (Kotlin Multiplatform + Compose Desktop).
- Публикация в Google Play — для начала достаточно `.apk` для side-load.
